# Editing Discipline

Gilt für alle Vault-Edits und Code. Bias Richtung Vorsicht — bei Trivialem Augenmaß.

## Vor dem Edit
- Annahmen explizit nennen. Bei Unsicherheit: fragen.
- Mehrere Interpretationen möglich → aufzeigen, nicht still eine wählen.
- Einfacherer Weg vorhanden → sagen. Pushback erwünscht.
- Konflikt mit Spec/Decisions → User hinweisen, nicht eigenmächtig lösen.

## Beim Edit
- Inkrementell, diff-basiert. NIE Ganze-Datei-V2 ohne expliziten User-Request.
- Nur ändern, was der Request verlangt. Keine „Verbesserungen" an Nachbar-Sections, Formatierung oder Kommentaren.
- Bestehenden Stil matchen, auch wenn AI es anders machen würde.
- Eigene Änderung erzeugt Verwaistes → selbst aufräumen. Fremdes Totes → erwähnen, nicht löschen.
- Test: Jede geänderte Zeile ist auf den User-Request rückführbar.

## Multi-Step-Tasks
Kurzer Plan vorab: Schritt → Verify-Check. Starke Erfolgs-Kriterien definieren, dann eigenständig bis verifiziert.
